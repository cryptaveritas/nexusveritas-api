## 3. Механики доступа (Token-Gated Access)

| Тир | Условие | Доступ |
|---|---|---|
| B2C Private | Hold 1,000 $VERAX | Приватные сигналы |
| B2B Lite | Hold 10,000 $VERAX | Базовый API |
| B2B Pro | Hold 50,000 $VERAX | Extended API + приоритетная поддержка |
| Enterprise | Официальный контракт | $VERAX / USDC / USDT / фиат |

**Сильные стороны:**
- Простая механика без транзакционного трения — токены не тратятся, работают как депозит
- Проверка через offchain RPC (hourly) — нет gas costs на каждый запрос
- Enterprise тир изолирован от токена — USDC/USDT/фиат

**Слабые стороны:**
- При падении цены $VERAX эффективная стоимость доступа меняется → нестабильный SLA для B2B Lite/Pro
- 1,000 VERAX для B2C — при высокой цене токена барьер входа растёт
- Hourly RPC check — окно в 1 час позволяет временно продать токены после проверки

**Рекомендация:** для B2B Lite/Pro зафиксировать минимальный holding period (например, 7 дней).

## 4. Механика Credit Wrapper

```
[ Enterprise ] → USDC → [ Credit Wrapper ] → $VERAX → Ноды / Burn
```

**Оценка:**
- Полная изоляция Enterprise от волатильности — корректно
- Автоматический выкуп через Jupiter создаёт buy pressure
- Дефляционное давление через burn

**Риски:**
- Проскальзывание при низкой ликвидности пула
- MEV-атаки на предсказуемый автоматический выкуп
- Смарт-контракт шлюза требует отдельного аудита

**Статус:** Фаза 3 — после первых B2B контрактов.

## 5. Механика Stake & Slash

**Критические проблемы:**

- **Оракульная проблема:** кто источник истины для консенсуса? NexusVeritas сам вычисляет поведенческие векторы — замкнутый круг
- **Минимальный порог нод:** механика не работает при N < 3-5 нод
- **Субъективность сигналов:** recycling_loop, split_init_pattern — не детерминированы как on-chain данные

**Статус:** Фаза 4 (Месяцы 6-12). До этого — преждевременно.
