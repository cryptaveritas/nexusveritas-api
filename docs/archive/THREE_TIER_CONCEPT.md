# NexusVeritas — Концепция трёх направлений
**Date:** 2026-06-14
**Status:** Internal only / концепция
**Предусловие:** реализуется ПОСЛЕ того как core (similarity, P50 < 0.85) доказан рабочим

---

## 0. Главный принцип (читать первым)

Разбиение на три направления — это **не три продукта**. Это **один движок (core) с тремя поверхностями доступа**. Если построить три отдельных продукта — получишь три полу-работающих фасада над одним сломанным ядром, и утроишь нагрузку поддержки в одиночку.

Правильная формула: ОДИН core engine (scoring + classification + graph) → тонкие поверхности: Consumer / Organizations / Research. Core остаётся единственным источником истины. Направления различаются только тем, сколько они показывают и как упаковывают.

## 1. Три направления

**Consumer** — трейдеры/держатели. Вопрос: "этот токен опасен — да/нет?". Формат: input → светофор + короткое объяснение.

**Organizations** — Phantom, Jupiter, launchpad'ы, биржи. Вопрос: "структурированный risk-сигнал в наш pipeline". Формат: API с risk_score + коды сигналов + граф + история.

**Research** — ты сам + security-исследователи. Вопрос: "найди новые паттерны, валидируй архетипы". Формат: сырые векторы, кластеры, candidate_discovery, разметка. Ключевая роль: фабрика фич для 1 и 2.

## 2. Дифференциация Consumer от конкурентов

Конкуренты (GoPlus, De.Fi) проверяют контракт. Ты проверяешь создателя.
Фраза для лендинга: "Другие проверяют контракт. Мы проверяем человека за ним."
Фича которой нет у них: профиль создателя — архетип, сколько токенов создал, связан ли с плохими хабами.
Оговорка FINDING_003: operator_class != token_risk. Честная формулировка: "создатель имеет высокорисковый профиль", не "токен — скам".

## 3. Organizations — где деньги

Consumer трудно монетизировать (retail не платит), Research не монетизируется напрямую. Деньги в B2B.
Что нужно организациям: risk_score 0-100, массив кодов сигналов, batch API, граф, SLA.
Расширения сюда: real-time мониторинг кошельков, webhook при смене архетипа, custom архетипы, historical replay.

## 4. Рекомендация: фазы, не параллельно

**Фаза A (сейчас → core работает):** только Research, внутренний. Это то что ты и так делаешь — фикс сигналов, P50, валидация.

**Фаза B (core доказан, P50<0.85, 1000+ creators):** Organizations API минимальный. /v2/scan/ с risk_score + matched_signals. Цель — один B2B-клиент.

**Фаза C (есть proof):** Consumer-поверхность. Тонкий лендинг поверх API. Воронка, не доход.

Research сквозной на всех фазах. Порядок: сначала деньги/proof (B), потом воронка (C).

## 5. Аргументы ЗА
Разная аудитория — разный язык. Research как воронка фич. Коммерческая ясность. Переиспользование core. Story для грантов.

## 6. Аргументы ПРОТИВ
Утроение поддержки. Преждевременность (core не доказан). Размытие фокуса. Consumer — ловушка времени (retail не платит). Maintenance vs progress.

## 7. Итог
Концепция верная, но ценность зависит от порядка. Три направления как фазы над одним core — сильно. Как параллельные продукты сейчас — ловушка.
Одной фразой: не три продукта, а один движок с тремя выходами по очереди — Research → Organizations → Consumer. Core сначала, поверхности потом.
